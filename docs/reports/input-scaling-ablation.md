# 入力スケーリングだけを直すアブレーション実験

元実装の他の問題を残したまま、84個の入力値だけを0〜1へ収めて、学習結果がどう変わるかを比較した。

## 変更したもの

各ポケモンの6入力を次のように変換した。

- ポケモンID: `id / 135`
- HP: `max(0, actual_hp) / max_hp`
- 技ID: `id / 9`
- activeフラグ: もともと0/1なので変更なし

入力数は84個のままである。IDのone-hot化はせず、大小関係に意味がないカテゴリ値を連続値として扱う問題も意図的に残した。

## 変更していないもの

- 10×10のMLP
- 途中で相手がRandomからAttackへ変わるカリキュラム
- 報酬
- 最大1,024件のReplay Buffer
- 1試合に1回の更新
- TDターゲット計算時に違法行動をマスクしない実装
- Target Networkなし

したがって、これは「入力の尺度」だけの効果を調べる実験であり、修正版DQN全体の評価ではない。

## 条件

- 各条件1,000試合学習
- seed 0〜4の5回
- 学習後は更新と探索を止める
- 固定種類のRandom/Attack相手へ各seed 300戦
- Python 3.10.20 / NumPy 1.23.2 / scikit-learn 1.1.2（`pyproject.toml`の指定に準拠）

## 結果

| seed | 生入力 vs Random | 0〜1入力 vs Random | 生入力 vs Attack | 0〜1入力 vs Attack |
|---:|---:|---:|---:|---:|
| 0 | 56.0% | 97.7% | 2.3% | 54.7% |
| 1 | 2.7% | 98.7% | 0.3% | 77.3% |
| 2 | 15.7% | 98.3% | 2.0% | 83.3% |
| 3 | 23.7% | 77.0% | 9.0% | 36.0% |
| 4 | 39.0% | 98.7% | 11.0% | 74.0% |
| **平均 ± 標準偏差** | **27.4 ± 20.7%** | **94.1 ± 9.5%** | **4.9 ± 4.7%** | **65.1 ± 19.5%** |

5 seedを合計すると、Random相手は生入力の411勝/1,500戦から、0〜1入力の1,411勝/1,500戦へ改善した。Attack相手は74勝/1,500戦から976勝/1,500戦へ改善した。引き分けはなかった。

## ReLUと状態識別

学習後のモデルへ同じ10盤面を入力した診断では、次の結果になった。

- 生入力のseed 0では、第1層の10ユニットすべてが停止し、10個すべてのQ出力が盤面間で同一になった。
- 生入力の他seedでは3〜8ユニットが反応し、必ず全ユニットが停止するわけではなかった。
- 0〜1入力では全seedで10個すべてのQ出力が盤面に応じて変化した。

「生入力なら常に全ReLUが停止する」わけではない。しかし、生入力はseed依存性が大きく、0〜1化すると全seedで状態依存の出力と大幅な勝率改善が確認できた。

## 結論

**入力の尺度だけを直しても、性能は大幅に改善した。** 特にAttack相手の平均勝率が4.9%から65.1%へ上がったため、入力スケーリングは学習失敗の主要因だったという仮説を強く支持する。

一方、Attack相手はseedによって36.0〜83.3%とばらつきが大きい。違法行動を含むTDターゲット、更新回数、Target Network不在などを残しているため、入力だけで安定したDQNになったとは言えない。

## 再現方法

```bash
python -m experiments.input_scaling_ablation \
  --episodes 1000 \
  --battles 300 \
  --seeds 0 1 2 3 4 \
  --output docs/reports/input-scaling-ablation.json
```

生データは [`input-scaling-ablation.json`](input-scaling-ablation.json) に保存している。
