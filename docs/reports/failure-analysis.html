01 / BACKGROUND

やりたかったこと

AIに対戦を何度も経験させ、「この盤面なら、どの技・交代が勝ちにつながるか」を自分で学ばせるプロジェクトです。

🎮

→
🧠
行動を選ぶ攻撃する？ 交代する？
→
🏅
点数をもらう勝利 +1、敗北 −1 など
→
📚
次に活かすよい行動の評価を上げる
🧩

状態（State）

今の対戦状況を数字の並びにしたもの。人間でいう「盤面を見る」に相当します。

⚡

行動（Action）

技を使う、控えのポケモンに交代する、という選択肢です。

📈

Q値（Q-value）

「この状況でこの行動をすると、将来どれくらい得か」の予想点です。

03 / ROOT CAUSES

失敗した4つの大きな理由

コードを読んだ結果と、実際に学習を再現した結果から、特に影響の大きい順に整理します。

01

勝率を測る「ものさし」が途中で変わった

序盤は弱い相手、終盤は強い相手。これでは前後の勝率を直接比べられません。

pokemon_ai/dqn/value_function_agent.py:103 
# 学習が進むほど JustAttackPlayer が選ばれやすくなる
if episodes / max_episodes < random():
    self.opponent = StupidRandomPlayer(build_random_team())
else:
    self.opponent = JustAttackPlayer(build_random_team())
序盤：ほぼランダム相手
無駄な交代が多い
終盤：ほぼ攻撃相手
毎ターンダメージ
同じ走者なのに、途中から上り坂に変えてタイムを比較しているようなもの。
02

入力の大きさがバラバラで、神経細胞が停止した

0/1のフラグとHP 413をそのまま混ぜたため、ネットワークが状態の違いを読めなくなりました。

再現実験では、異なる10個の盤面すべてでQ値が完全に同じになりました。AI生成版はHPを「残りHP ÷ 最大HP」にして0〜1へ揃えています。
03

実行できない行動まで「最高の未来」として採点した

Q値の最大を取るとき、瀕死のポケモンへの交代などを除外していません。

pokemon_ai/dqn/value_function_agent.py:123 
# future には合法・違法を含む10行動の予想が入っている
reward += GAMMA * np.max(future[i])
技0: 0.6 技1: 0.8 瀕死へ交代: 9.9 ← 最大 自分自身へ交代: 2.1

本当は選べない「9.9」を正解として学習すると、Q値が現実から離れていきます。AI生成版は next_mask で違法行動を最大値の候補から外します。

# AI生成版
next_q = np.where(next_masks, next_q, -np.inf)
best_next = next_q.max(axis=1)
04

1試合に1回しか学習しなかった

経験は何十手も集めるのに、ニューラルネットの更新は試合終了後の1回だけです。

pokemon_ai/dqn/trainer.py:84–85 
# while（対戦）が全部終わってから、1回だけ更新
if len(self.experiences) > 64:
    self.agent.update(sample(self.experiences, 64))
約 1,000自作版：1,000試合の更新回数
VS
168,625AI版：4,000試合の更新回数

AI生成版は経験を1つ保存するたびに学習します。また、一定期間固定した「答え用ネットワーク（target network）」を持ち、正解が毎回動くのを抑えています。

04 / CODE WALKTHROUGH

自作コードの1ターンを追いかける

どこで問題が入るのかを、実際の処理順に見てみます。

現在の処理

1
盤面を84個の数字にするIDやHPをそのまま入力。大きさが揃っていない。
2
10行動のQ値を予想ε=0.2なので、学習の最後まで20%はランダム。
3
対戦を1ターン進める与えた・受けたダメージと勝敗から報酬を作る。
4
経験を最大1,024件保存状態、行動、報酬、次の状態を記録。
5
試合終了後に1回更新違法行動を含む最大Q値を答えに使う。

AI生成版で追加された安全装置

✓
0〜1中心の入力HP割合、生存フラグ、選出中フラグで表現。
✓
合法行動マスク行動時だけでなく、次のQ値の計算にも利用。
✓
Target Network少し古いコピーを正解計算に使い、学習を安定化。
✓
経験ごとに更新試合中にも何度もミニバッチ学習する。
✓
固定テスト学習とは別に、同じ基準で200戦ずつ評価。
もう1つの問題： 自作版の replay は、保存モデルを読み込んだあとも Trainer.train() を呼びます。つまり「テスト」のつもりでもモデルを更新してしまい、純粋な評価になっていません。

06 / REPAIR PLAN

直すなら、この順番

いきなり6対6を完成させず、小さな成功を確認してから難しくします。

学習と評価を完全に分ける評価中は更新なし・探索なし。固定相手、固定乱数、先攻後攻を半分ずつにする。
入力を0〜1付近に揃えるHPは割合、種類や技はone-hot表現。ID番号を「大小に意味がある数」として渡さない。
違法行動を2か所で隠す行動選択時と、次状態の最大Q値を計算するときの両方にマスクを使う。
Target Networkを入れる学習中のネットワーク自身を、その瞬間の正解として使わない。
1手ごとに学習する大きめのリプレイバッファから64件ほど取り、試合中にも更新する。
まず固定3対3で成功させるグラフで改善を確認してから、技数、ランダムチーム、6対6を1つずつ追加する。
自己対戦には過去モデルを混ぜる最新の自分だけを相手にすると戦略がぐるぐる変わるため、過去のスナップショットも使う。
要点

「もっと学習」より先に「正しく測る・正しく入力する」

自作版は完全に何も学べなかったわけではありません。ランダム相手には改善しました。しかし、評価方法がそれを隠し、ネットワークの停止と不安定なQ学習が本格的な戦略獲得を妨げました。
