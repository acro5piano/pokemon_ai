「声の大きさ」が違いすぎた

02 / ONE CHANGE

変更はひとつ。
全部を0〜1に収める

ネットワークも報酬も学習回数も変えません。ポケモン1体を表す6個の数字だけを割り算しました。

BEFORE — 生の数字
def to_array(self):
    return [
        self.id,
        self.actual_hp,
        *[move.id for move in self.actual_moves],
    ]
例：[135, 333, 3, 4, 7, 8]
AFTER — 0〜1へ変換
def scaled_to_array(self):
    return [
        self.id / 135,
        max(0, self.actual_hp) / max_hp,
        *[move.id / 9 for move in self.actual_moves],
    ]
例：[1.0, 1.0, 0.33, 0.44, 0.78, 0.89]
SPECIES

ポケモンID

135 ÷ 135 = 1.00
最大でも1
HIT POINT

残りHP

206 ÷ 413 ≒ 0.50
「半分残っている」と表現
MOVE

技ID

9 ÷ 9 = 1.00
最大でも1
重要： IDを割り算しても、IDに本当の大小関係がない問題は残ります。今回は「大きさをそろえる効果」だけを見るため、あえてone-hot化していません。
03 / WALKTHROUGH

同じ条件で、
生入力と0〜1入力を対決

ほかの修正が勝率へ混ざらないように、入力以外は元実装のままです。このように一要素だけ変える比較を「アブレーション実験」と呼びます。

変えずに残した条件

10 × 10小さなニューラルネット
1回 / 試合少ない学習更新
Maskなし違法行動も未来の候補
Targetなし動く自分を教師にする
つまり、結果に大差が出たなら、その主な違いは入力を0〜1へそろえたことです。
STEP 1乱数を固定

seed 0〜4の5パターンを用意。偶然の当たり外れを確認します。

STEP 22種類を学習

生入力版と0〜1版を、それぞれ1,000試合学習させます。

STEP 3学習を停止

評価中は重みを更新せず、ランダム探索も0にします。

STEP 4固定相手と対戦

RandomとAttackへ、それぞれ300戦ずつ挑みます。

STEP 5平均を比較

5 seedの平均と標準偏差を計算します。

再現コマンド
python -m experiments.input_scaling_ablation \
  --episodes 1000 \
  --battles 300 \
  --seeds 0 1 2 3 4 \
  --output docs/reports/input-scaling-ablation.json

05 / TAKEAWAY

大成功。でも、
これで完成ではない

入力スケーリングの重要性は確認できました。同時に、次に直すべき問題もはっきり残っています。

LIMIT 01

seed差がまだ大きい

0〜1版のAttack勝率は36.0〜83.3%。初期値や対戦の偶然に左右されています。

LIMIT 02

IDはまだ連続値

135が121より「大きい種類」という意味はありません。次はone-hot表現が候補です。

LIMIT 03

DQNの欠点は未修正

違法行動のQ値、更新不足、Target Network不在は、そのまま残しています。

CONCLUSION

AIには、数字の「意味」だけでなく「尺度」も伝える。

大きな数字をたくさん入れれば情報が増えるわけではありません。比較しやすい形へ整えて初めて、ニューラルネットは盤面の違いを学べます。今回の実験では、その前処理だけで弱かったAIが明確に強くなりました。
