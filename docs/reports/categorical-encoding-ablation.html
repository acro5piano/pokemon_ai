01 / PROBLEM

図鑑番号は「名前」なのに、
AIには「量」に見える

図鑑番号はポケモンを見分けるラベルです。しかし数字をそのまま渡すと、ニューラルネットは数直線上の量として計算します。

AIが受け取っていた数字

0〜1化しても、順序と距離は残ります。

112サイドン
121スターミー
135サンダース

でも、この意味は存在しない

番号は住所の番地に近く、能力の量ではありません。

× サンダースはスターミーの約1.12倍
× スターミーはサイドンに近い種類
× 番号が大きいほど強い

03 / CODE

実装は「一致した場所を1」

特別なライブラリは不要です。カテゴリ一覧を決め、入力値と同じ場所だけ1.0にします。

BEFORE — 数字1個
def scaled_to_array(self):
    return [
        self.id / 135,
        self.actual_hp / max_hp,
        *[move.id / 9 for move in self.actual_moves],
    ]
サンダース：135 / 135 = 1.0
AFTER — 種類ごとのスイッチ
SPECIES_IDS = (112, 121, 135)


def one_hot(value, categories):
    return [
        1.0 if value == category else 0.0
        for category in categories
    ]


def species_onehot_to_array(self):
    return [
        *one_hot(self.id, SPECIES_IDS),
        self.actual_hp / max_hp,
        *[move.id / 9 for move in self.actual_moves],
    ]
サンダース：[0.0, 0.0, 1.0]
01active今、場に出ているか
02species × 33種類のone-hot
03HP fraction残りHPを0〜1で表現
04moves × 4技IDは今回は0〜1化のまま

06 / WHY & NEXT

なぜ「全部one-hot」が
一番ではなかった？

正しい表現でも、情報を増やしすぎれば良いとは限りません。

入力だけが約4.6倍

隠れ層は10×10のままなのに、技のスイッチで入口だけが大きくなりました。

108種類だけ
→
492種類＋技

技は種類から予想できる

この実験では各ポケモンの技が固定です。種類と技を両方細かく渡すと、同じことを重ねて教えやすくなります。

サンダース → いつも同じ4技
スターミー → いつも同じ4技
サイドン → いつも同じ4技

種類が何百もあるならembedding

one-hotは種類の数だけスイッチが必要です。embeddingは、種類番号を短い「学習できる特徴ベクトル」へ変換します。

種類が少ないone-hotが簡単で分かりやすい
種類が多いembeddingが省スペース
PyTorchでの例
# 3種類を、学習可能な4個の数字へ変換
embedding = torch.nn.Embedding(
    num_embeddings=3,
    embedding_dim=4,
)

# 2番 = サンダース
species_index = torch.tensor([2])
species_vector = embedding(species_index)

# 例: [-0.21, 0.84, 0.37, -0.15]
# 値は対戦学習と一緒に更新される
CAUTION 01

入力層も大きくなった

one-hot化でパラメータ数も増えたため、改善のすべてを意味表現だけの効果とは断定できません。

CAUTION 02

5 seedの小規模実験

差は大きいものの、さらに多くのseedや別チームでも再確認する余地があります。

CAUTION 03

DQNの欠点は残る

違法行動のQ値、更新不足、Target Network不在は今回も修正していません。

CONCLUSION

IDは量ではない。「どれか」を独立して伝える。

この3種類の環境では、図鑑番号を1個の数字として渡すより、3個のスイッチへ変換する方が強く安定しました。少ないカテゴリならone-hot、多数のカテゴリならembedding。データの意味に合った入口を作ることが、ニューラルネットの学びやすさを変えます。
