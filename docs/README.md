# プロジェクトから得られた知見

このディレクトリは、`pokemon_ai` をアーカイブする時点で得られた知見を残すためのものです。対象となる元実装は `7db12d1` です。

## 結論

元実装はまったく学習していなかったわけではありません。固定したランダム相手への勝率は、再現実験で学習前の **4.0%** から学習後の **76.7%** まで改善しました。しかし、攻撃を続ける相手には **3.7%** しか勝てませんでした。

主な問題は、学習量の不足よりも次の設計にありました。

1. **評価基準が学習途中で変わっていた**  
   序盤はランダム相手、終盤は攻撃型の相手が増えるため、表示された勝率を時系列で比較できませんでした。
2. **入力値の尺度と表現が不適切だった**  
   0/1フラグ、技ID、ポケモンID、最大413のHPをそのまま同じネットワークへ入力していました。再現実験では第1層のReLUがすべて停止し、異なる盤面に同じQ値を返す状態が確認されました。また、IDを連続量として扱うことにも意味上の問題があります。
3. **TDターゲットの計算で合法手をマスクしていなかった**  
   次状態の最大Q値を取る際、瀕死のポケモンへの交代や自分自身への交代も候補に含めていました。実行不能な行動のQ値が高いと、それを「最良の未来」として学習してしまいます。
4. **学習更新が少なく、不安定化を防ぐ仕組みもなかった**  
   何十手分もの経験を集めても更新は1試合に1回だけでした。Target Networkもなく、学習中のネットワーク自身が動き続ける教師になっていました。
5. **学習と評価が分離されていなかった**  
   `replay` も保存モデルを読み込んだ後に `Trainer.train()` を呼ぶため、評価中にモデルが更新されます。探索率だけを0にしても純粋な評価にはなりません。

## 参考実装から学べる設計

AIが生成した[比較用実装](../reference/ai-generated-self-play-dqn/)は、元実装と同じ難易度の問題を解いたものではありません。固定3対3、5行動、19入力という小さな問題へ落としたうえで、まず学習可能性を確認しています。この単純化自体が重要な設計判断です。

採用されていた主な仕組みは次のとおりです。

- HPを割合にし、状態を主に0〜1の値で表現する
- 行動選択時とTDターゲット計算時の両方で合法手をマスクする
- 128×128のネットワーク、最大5万件のReplay Buffer、64件のミニバッチを使う
- 経験を追加するたびに更新し、Target Networkを定期同期する
- 探索率を1.0から0.05まで徐々に下げる
- 1つの方策で自己対戦しつつ、過去モデルのリーグとも対戦する
- リーグが現在の方策と一緒に漂流しないよう、満杯時は古い順ではなくランダムに置換する
- 学習とは別に、固定したRandom/Greedy相手へ探索なしで定期評価する
- 評価値が最良だったチェックポイントを保存する

比較用実装は4,000試合で168,625回更新され、最終チェックポイントの報告値はRandom相手 **92.5%**、Greedy相手 **99.5%** でした。保存モデルを各1,000戦で再評価した別実験でも、それぞれ **92.2%** と **99.2%** でした。

## 数字の解釈に関する注意

- 比較用実装は固定3体、技の必中、急所・状態異常・PPなしなど、元実装より大幅に簡略化されています。勝率を直接比較して「同じ問題で優れている」とは言えません。
- 評価相手はRandomとGreedyの2種類だけで、人間や交代を読む相手への強さは未確認です。
- 報告された本学習は `seed=0` の1回です。再現性を主張するには複数seedの平均と分散が必要です。
- 三すくみの自己対戦では方策が循環します。損失が下がっても、特定の固定相手への勝率は単調には上がりません。
- 高い勝率のモデルにも、無効な技を繰り返すなどの無駄な行動が残っていました。

## 今後、同種のプロジェクトを始めるなら

1. 学習と評価を完全に分け、固定条件のベースラインを最初に作る
2. 1対1または固定3対3の小さな環境で学習できることを確認する
3. 入力を正規化し、カテゴリ値はone-hotなどで表現する
4. 合法手マスク、Replay Buffer、Target Networkを先に正しく実装する
5. 複数seedで平均・分散を記録し、最良値だけで判断しない
6. 相手、チーム、技、ルールの複雑さを一度に増やさず、1要素ずつ追加する
7. 自己対戦では過去方策を保持し、忘却と循環を監視する
